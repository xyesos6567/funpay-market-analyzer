# Анализатор рынка FunPay

Инструмент для продавцов ИИ-доступов на FunPay: собирает предложения конкурентов,
считает юнит-экономику, находит слабые места ваших лотов и выдаёт список
конкретных изменений с приоритетами.

Отчёт — один самодостаточный HTML-файл, который открывается в браузере.

## Зачем это нужно

В этой нише цены нельзя сравнивать «в лоб». Лоты продаются паками разного объёма:
25M токенов за 20 ₽ и 25B токенов за 1500 ₽ — это разные продукты. Поэтому
инструмент переводит всё в единую метрику — **рубли за 1M токенов** — и только
после этого сравнивает.

Пример реального вывода: пак DeepSeek V4 Flash 25B у анализируемого продавца
стоит 0.06 ₽/1M, а медиана среди 27 сопоставимых по объёму лотов конкурентов —
0.34 ₽/1M. То есть продавец отдаёт токены на 82% дешевле рынка.

## Быстрый старт

**Самый простой способ:** откройте папку проекта и дважды кликните по `run.bat`.
Скрипт сам найдёт Python, создаст окружение, установит зависимости, запустит
анализ и откроет отчёт в браузере.

Важно: запускать нужно именно `run.bat` (или команду ниже) **из папки проекта**.
Если просто набрать `python`, откроется интерактивная оболочка Python —
это не запуск анализа, из неё нужно выйти командой `exit()`.

Вручную:

```bat
cd /d C:\path\to\funpay-market-analyzer
winget install --id Python.Python.3.12 --exact --source winget
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m analyzer run
```

Либо, если окружение уже создано:

```bat
cd /d C:\path\to\funpay-market-analyzer
.venv\Scripts\python.exe -m analyzer run
```

Отчёт появится в `out\report.html`, машинно-читаемые данные — в `out\data.json`.

### Команды

| Команда | Что делает |
|---|---|
| `python -m analyzer run` | Полный цикл: автопоиск, сбор, аналитика, отчёт |
| `python -m analyzer discover` | Только автопоиск категорий, без сбора лотов |
| `python -m analyzer report` | Пересобрать HTML из сохранённого `data.json`, без обращений к сети |
| `python -m pytest` | Тесты, включая регрессии на разметку FunPay |

## Что анализируется

По каждой категории:

- **Распределение цен** лота: минимум, p10, p25, медиана, p75, p90, максимум.
- **Юнит-экономика**: цена за 1M токенов по каждому лоту и по рынку.
- **Ваши лоты против рынка**: у каждого лота — сколько найдено сопоставимых
  предложений и на сколько процентов вы дороже или дешевле медианы.
- **Конкуренты сверху** с композитным баллом: отзывы (40%), рейтинг (20%),
  онлайн-статус (15%), автовыдача (15%), промо (10%).
- **Свободные нишы**: ценовые зоны, где спрос выше среднего, а предложения мало.
- **Покрытие моделей**: какие модели продают лидеры, а у вас их нет.

## Правила рекомендаций

| Код | Что проверяет |
|---|---|
| R1 | Цена лота в самом низу или в самом верху рынка |
| R2 | Цена за 1M токенов против сопоставимых по объёму лотов |
| R3 | Последовательность скидок за объём, разрывы между паками |
| R4 | Смыслы в описаниях, которые используют лидеры, а вы — нет |
| R5 | Автовыдача отсутствует там, где у конкурентов она есть |
| R7 | Модели, которые продают конкуренты сверху, но нет у вас |
| R8 | Свободные ценовые зоны с повышенным спросом |
| R9 | Сверхдешёвые лоты-якоря, снижающие средний чек |
| R10 | Описания короче, чем у лидеров |
| R11 | **В описании обещано «авто», но флаг автовыдачи не включён** |
| R12 | Вас нет в категории, где идёт активная торговля |

Приоритеты: **P0** — прямая потеря денег или трафика, **P1** — заметный эффект,
**P2** — оптимизация.

R11 стоит пояснить отдельно: если в описании лота написано «авто», а признак
автовыдачи в настройках не выставлен, лот не попадает в фильтр «с автовыдачей».
Покупатель, который ищет моментальную выдачу, просто не увидит такое предложение.

## Автопоиск похожих категорий

Отдельно указывать категории не нужно. Инструмент скачивает каталог с главной
страницы FunPay (около 900 игр с подкатегориями), находит ИИ-сервисы и берёт
внутри них только «сервисные» подкатегории — токены, API, подписки, услуги.

Кандидаты сортируются по близости к товару продавца: сначала «Токены» и API,
затем подписки, промокоды и услуги. Аккаунты не берутся — продавец торгует
доступами, а не аккаунтами.

## Настройка

Всё в `config.yaml`, код трогать не нужно.

```yaml
seller:
  id: 4233111          # чей ассортимент анализируем
  name: POLICEA
  brand: VibeTokens

discovery:
  max_extra_categories: 20   # сколько категорий добавит автопоиск
  keywords: [...]            # доп. слова к встроенному списку ИИ-игр
  exclude_games: [...]       # что исключить, если совпало случайно

http:
  delay_seconds: 2.0         # пауза между запросами
  cache_ttl_minutes: 60      # кэш скачанных страниц

advice:
  price_deviation_threshold_pct: 15   # порог отклонения цены для совета
  desired_phrases: [...]              # смыслы, наличие которых проверяем
```

Повторный запуск в течение часа берёт страницы из кэша — быстро и без лишней
нагрузки на сайт.

## Ограничения и честные оговорки

- **Точных данных о продажах FunPay не публикует.** Спрос оценивается косвенно,
  по числу отзывов продавца. Это прокси: он не идеален, но именно отзывы и рейтинг
  определяют, кого покупатель видит первым. Все выводы о «спросе» — это выводы
  о репутации, а не о фактических продажах.
- **Сравнение только по сопоставимому объёму.** Если для вашего лота на рынке нет
  паков похожего размера, инструмент честно сообщит об этом и не станет сравнивать
  цену с паком, отличающимся на порядок.
- **Маленькая выборка понижает приоритет.** Вывод по 3–4 аналогам не подаётся
  как критичный: в доказательстве появляется пометка о малой выборке.
- **Разметка FunPay может измениться.** Парсер при неожиданной разметке падает
  с явной ошибкой, а не отдаёт пустой отчёт. Тесты на сохранённых страницах
  поймают поломку раньше, чем вы поверите неверным числам.
- **Автоматический сбор данных может противоречить правилам FunPay.** Инструмент
  работает только с публичными страницами, без авторизации и обхода защит,
  с паузой между запросами и кэшем. Ответственность за использование — на вас.

## Структура проекта

```
analyzer/
  config.py       загрузка и валидация config.yaml
  http.py         запросы, ретраи, пауза, дисковый кэш
  parse.py        разбор HTML в объекты Offer
  normalize.py    объёмы токенов и рубли за 1M токенов
  discover.py     автопоиск похожих категорий
  competitors.py  агрегация по продавцам и скоринг
  analytics.py    распределения, позиционирование, свободные зоны
  advice.py       правила рекомендаций
  report.py       сборка контекста и рендер отчёта
  cli.py          командный интерфейс
templates/report.html.j2   шаблон дашборда
tests/                     тесты, включая фикстуры реальных страниц
data/cache/                скачанные страницы
out/                       отчёты и JSON
```

## Тесты

```bat
.venv\Scripts\python.exe -m pytest
```

85 тестов, в том числе регрессионные на реальном HTML FunPay. Они фиксируют
эталонные числа (медиана цен в категории, число лотов продавца) и защищают от
классических ошибок этой задачи: ложное распознавание объёма («25 000 кредитов»
не токены) и сравнение паков разного размера.
